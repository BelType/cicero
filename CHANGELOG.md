# Changelog

## Unreleased

- **A hanging number composes (Codeberg issue 7, narrowly).** The padding fix of 0.1.11 covered a float that is a sibling of the block; a number inside the block, `<p class="comma"><span class="num">1.</span> …</p>` with `.num { float: left; margin-left: -1.4em }`, was still refused, because a floated child computes `display: block` and `isComposable`'s child check (`isInlineBox`) turned the whole paragraph away. `isOutsideMarker` in `src/word-space.ts` now names a float child that stands wholly outside its parent's content box, in the padding or the border; `isComposable` lets it pass and `collectWords` leaves it out of the text being set, so it stays where the browser put it. Any other floated child still refuses the block, and a float that intrudes on the content box still refuses it beside a float. Measured 2026-11-08 on the Trattato (`specimens/trattato`, 1 348 paragraphs, 753 with a `.num` child) by `isComposable` on the unrun document: 595 composable paragraphs before and none of the 753 numbered ones, 1 348 after and all 753. Held in `test/browser/composed-refusals.browser.ts` (`hang-child`, `intruding-child`).
- **The reads loop writes a sheet only when its text changed, and logs only when something is unsettled.** `deliver` and `hideReservations` called `replaceSync` on every settle, which restyles the document whether or not a value differs, and every settle wrote the `pages settled in N runs` line to the console; a host that settles on each keystroke paid both each time. `src/reads.ts` keeps the last text of each engine sheet and returns before `replaceSync` when it is the same, and the summary line is written only when a page number still moves its own lines (the warning of that case stays). Held in `test/reads-hosts.test.ts` (two identical settles: one write, no log). The adopted-sheet reassignments were already guarded by `includes`.

## 0.1.11 — 2026-11-08

- **The end of a paragraph cut at a hyphen the browser drew is no longer lost to a printer (Codeberg issue 14).** 0.1.10 (`d7e7c7e`, *a page cut falls at a line the browser hyphenated under `hyphens: auto`*) wrote that hyphen into the last kept text node of the first fragment, so the node read `conse‐` where the source reads `consequat`. A printer locates a fragment by its text inside its source's own text nodes, folding a trailing hyphen only into a soft hyphen the source holds, so it found none, took the piece for text the engine wrote, and Caster's tiling invariant refused the print of the studio's Quiet Press for characters "presented on no page" (4 paragraphs, 749 characters). The first fragment now keeps its letters alone and the hyphen stands as the Compositor's does: a text node of its own, the engine's, before a `<br data-beltype="break">`, written after the leave-out and the structural pass that would take it for spent (`consumeTrailingWords` in `src/fragments.ts`). Chromium's print is unchanged (`test/browser/hyphen-at-the-cut.browser.ts`). Proved by `test/browser/split-paragraph-tail.browser.ts`, red on 0.1.10, and by the writer's case in `test/fragments.test.ts`.
- **A numbered `ul` a page cut divides numbers its items on from the page before.** `numberDividedLists` in `src/fragments.ts` handled `<ol>` only, so a `ul { list-style-type: decimal }` (or a `menu`) numbered from 1 again on every page it continued onto. HTML's `start` belongs to `ol` alone and Chromium's marker ignores a `counter-reset` of `list-item` (both measured 2026-11-08), so the continued copy of a `ul` or `menu` carries a `value` on its first kept item instead. Held against Chromium's print, in both modes, by `a ul with a numeric list-style-type divided by a page cut numbers its items as Chromium prints them` in `test/browser/list-continuation.browser.ts`.
- **A flow site that reads `counter(pages)` is hidden until the total is known.** `p::before { content: counter(pages) }` in the flow showed its reservation, `0`, on every page of a paced `run({ until: { pages: 1 } })`, though the page total is blank until the run is complete (`src/chase.ts`); `hideReservations` hid only cross-reference reservations. `totalSites` in `src/reads.ts` names the rules that read the total, `settleReads` hides them with the reservations, and the sheet comes off when the run completes. Proved by `test/browser/page-total-early.browser.ts`.
- **The composed mode reads the author's `hyphenate-limit-lines`.** Chromium drops the property at parse, so the Compositor always used its own limit of three. The host's sheet rewrite (`seam/rewrite.ts`) now renames the declaration to `--beltype-hyphenate-limit-lines`, value verbatim, like `string-set`; it inherits as the property does, so it is not registered. `limitLinesOf` in `src/compose-dom.ts` reads it (`no-limit` lifts the limit, an integer sets it, anything else keeps the engine's three) and it joins the paragraph's cache key. Proved by `an author's hyphenate-limit-lines of 1 ends at most one line in a row on a hyphen` in `test/browser/hyphen-limit-lines.browser.ts` and a rewrite case in `test/rewrite.test.ts`.
- **A malformed URL fragment no longer throws.** `#%E0%A4%A` made `decodeURIComponent` throw in `<beltype-root>`'s hash handler (`src/root.ts`), in the client's first-run reveal (`seam/client.ts`) and in the bootstrap the engine emits (`seam/index.ts`). The first two now call `decodeFragment` (`src/data-beltype.ts`), which returns the raw text when it is not valid percent-encoding; the bootstrap is a string of page script and cannot import, so it carries the same try and catch inline. `test/data-beltype.test.ts` holds the function (assessment 2026-11-07, `malformed-hash-throws`).
- **The `cssText` fallback for a margin box's content is gone.** `marginBoxesOf` (`src/capture.ts`) fell back to a regex over `rule.cssText` when a page rule showed no `CSSMarginRule` children. `test/browser/margin-box-padding.browser.ts` asserts that `CSSMarginRule` exists in the pinned Chromium, and the fallback is deleted. `readPageGeometry` (`src/driver.ts`) is a different regex, over the page rule's own `size` and `margin`, which that assertion does not cover; it stays (`marginboxesof-regex-fallback`).
- **A margin box's own font and size are claimed.** `@top-center { content: "x"; font: 9pt serif }` reads 12px and a serif family on the presented page, held in `test/browser/margin-box-padding.browser.ts`; green on main, a guard (`margin-box-face-size-case`).
- **SPEC Article XIII says nine faces and the fragmentation face lists what it exports.** The article said four, then five, against the nine `package.json` entries (`.`, `./engine`, `./flags`, `./rewrite`, `./facsimile`, `./client`, `./rim`, `./fragmentation`, `./page`); it now carries the table, and `firstBelowTheEdge` joins the `stonehand` row. `src/fragmentation.ts` re-exports `sheetReach` and `findSites`, which the article listed and the face omitted, and points at `./page`, not `internal/chase`. `test/faces.test.ts` compares SPEC's tables with `exports` and with the face's names (`spec-faces-drift`).
- **A multi-column box keeps the browser's lines in composed mode.** The Compositor has one measure per block and reads it from the block's own box, so a `columns: 3` box 210 px wide was set at the container's measure, its longest line wider than a column by several times. `isComposable` now refuses a block that is, or stands inside, a box whose `column-count` or `column-width` is not `auto` (`inColumns`, `src/compose-dom.ts`), and the console says so on every run, as it does for a block beside a float. The fix that composes a column is a per-column measure and the fragmentation of a multi-column box, not this engine's yet. `test/browser/composed-refusals.browser.ts` holds the paragraph that is itself the columns and the one inside a columns box, no line wider than its column, red before (assessment 2026-11-07, `composed-multicol-overruns`).
- **A float in a block's padding no longer keeps the block from the Compositor (Codeberg issue 7).** The beside-a-float refusal compared the float's rect with the block's border box, so a hanging number, floated left into the paragraph's padding, always overlapped it and legal and numbered text was never composed. It now compares with the block's content box: a float wholly in the padding or the border shortens none of its line boxes, and one that reaches into the content is refused as before. `test/browser/composed-refusals.browser.ts` holds a `.num` floated into a `.comma`'s left padding, composed, and a float beside the text, still refused, red before (`issue-7-hanging-numbers-not-composed`). The row's own case is not closed: the numbered text of the trattato specimen (`specimens/trattato`, 188 pages) writes its number as a `<span class="num">` floated into the `.comma`'s padding, and a floated child computes `display: block`, so `isComposable` refuses the paragraph before the float test is reached. Composed on that document before and after this change: 0 composed breaks and no beside-a-float refusal both times. Composing it asks for floated children to leave the word space, as a fixed box does, which is a design choice and waits on a ruling.
- **A paragraph nested in a block is measured in the block's styles, and a pull quote's composed lines fit its box.** The Compositor measured advance widths on a copy of the paragraph alone, set in the measure container, so what the paragraph inherits from its ancestors and what a descendant selector reads (`blockquote { font: italic 22px serif }`) was lost, and the lines were chosen against the container's 16px: in an italic 22px serif quote in a 366 px box the composed lines were 437 to 454 px wide, where the browser's own were 366. The copy is now seated inside shallow copies of its ancestors up to its top-level block (`measureRoots`, `src/compose-dom.ts`); a sibling selector (`p + p`, `:first-child`) still reads the lone copy, named in a `ponytail:` comment. The report in the studio (`composed-pull-quote-overrun`) read 348 px in 366 on main in system fonts and so was thought not reproduced; the studio's `quiet-press` demo in its web faces sets its font on the document, not the quote, and measures 363 in 363 either way, so the demo itself was never the case. `test/browser/composed-refusals.browser.ts` holds the quote, red before (widest line 453.8 px in a 366 px box).

## 0.1.10 — 2026-11-08

- **A PDF embed whose fallback image has no alt can warn instead of refusing, for an editor.** `install(doc, present)` in `seam/facsimile.ts` refused such a source at intake by throwing, so an editor built on the engine (prosemirror-beltype) failed every page of a document that held one. It takes a third argument, `{ missingAlt?: 'refuse' | 'warn' }`, default `'refuse'`, which keeps the throw and its wording. Under `'warn'` each such source is told once by `console.warn`, naming the element as the throw does, and its copy carries no `role` and no `aria-label`, so Caster's structure walk refuses it at print by name as before (Egildo's ruling of 2026-11-08). `test/browser/facsimile.browser.ts` holds both modes.
- **A rule that only paints no longer turns the forcing memo off, and the console names the rule that does.** One `section:has(> h1) { background: #eee }` anywhere put the memo out of use for the whole document, and a `p + p { color: red }` narrowed it, though neither moves a box. `sheetReach` and `topLevelReach` in `src/capture.ts` now pass over a style rule whose every declaration is on the closed `PAINT_ONLY` list (colours, backgrounds, opacity, shadows, filters, cursor and their kin; a custom property counts as layout), whatever its selector, and an `@container` or `@scope` rule all of whose nested rules paint. `sheetReachOf` and `topLevelReachOf` return the level with the first rule that set it, its sheet and how many more reached as far, and `ForcingMemo.notice` turns that into one console line per memo life at each level, at 1 as well as at 2, which was silent; `topLevelReach` keeps its number, so a view adapter's call is unchanged.
- **The intake passes over what never renders and over a host's own machinery.** `topLevelBoxes` in `src/driver.ts` took every element child of the root but engine scaffolding, `STYLE` and `SCRIPT`, so a hidden `<iframe>`, a `<template>`, a `<link>` or a `<noscript>` a host left in the body was a block of the document, got an address and shifted every address after it (a `<noscript>`'s text was even counted as words). The filter now also passes over `TEMPLATE`, `LINK`, `META`, `BASE`, `TITLE`, `HEAD` and `NOSCRIPT`, a closed list named in its TSDoc, and over any element carrying the new `host` word on `data-beltype` (`HOST` in `src/data-beltype.ts`, a flag a host writes; SPEC VI.2.5). It is the one filter: `seam/client.ts`'s intake, which kept a second copy of the line, now imports `topLevelBoxes`. A host that holds the document in an element of its own still names it with `root` first. `test/browser/intake.browser.ts` holds the four elements between two paragraphs: the driver's top-level blocks are the paragraphs alone, and through the client the addresses and the words on each page equal the clean document's, red before (ruled 2026-11-08).
- **A running element's edit is a chrome event, and costs no run.** `patch` returned `null` for a top-level running element, so a host that edited a running head reloaded or ran the whole document, though a running element is out of the flow and drawn in margin boxes of fixed size, so a word changed there moves no cut. `patch` at a top-level running element, or at a box inside one, now swaps the replacement into the run's list of running elements, draws again the chrome of every standing page whose `closes.running` names it (`redrawRunning` in `src/root.ts`, the kept page's own redraw), and answers `{ chrome: true }`; `run({ resumeAt })` with that answer cuts nothing and answers at once, `resumed` `{ from: 1, to: 0, shift: 0, converged: true, kept: pages }`. The `box(i)` door now answers a running element too, since a host reads the old box through it before it patches. Refused as before: a replacement that no longer names the same running element, any running edit while a sheet holds a `:has()` or a container query, and a running element nested in a block. A named string set from a running element is unread, so the reads loop's caveat does not arise. `test/browser/running-edit.browser.ts` holds a head on three pages edited whole and inside, every page showing the new head with the Ledger unchanged and no pagination or presentation, red before (SPEC XI.2.5, XII.1.5; Egildo's ruling of 2026-11-08).
- **The first pages no longer wait for the document's pictures, and a picture that arrives resumes only where it changed its box.** The intake awaited every image of the document before the first cut, and the driver awaited them again, so a document whose pictures came late showed nothing until the last of them had come: on a 59-page document with 60 images served 300 to 800 ms late, the first paint was 5.8 s, and 0.74 s with the two awaits gone (measured 2026-11-08, the monorepo's `.claude/plans/quick-rulings-2026-11-08/image-await.md`). Both are retired, on Egildo's ruling of that day: the driver makes a `loading="lazy"` image eager (`eagerImages`, `src/measure.ts`) and waits for none, and its `cicero:images` measure times that pass, `detail.awaited` false. The rim (`seam/rim.ts`) heard every load and resumed for each, 59 resumes that moved nothing in that measurement; it now judges a `load` or an `error` when the runs have ended, against the height the last run measured, and a box drawn as itself at that height is no signal. Declaring an image's `width` and `height` is what gives the fast first paint with nothing moved. The slice's own clone await (`awaitCloneImages`) stays until a document a Service Worker controls is measured without it. `test/browser/images.browser.ts` proves the first pages presented with no picture arrived, the final pages equal to a preloaded run, and one resume for a picture that grew its box against none for one that did not.
- **A fixed box or a running element written inside a block stays in it, and an edit inside that block is patched.** The intake lifted every such element out of its block and made it a light child of `<beltype-root>`, and `patch` refused any edit inside a block one was lifted from, since the host's tree and the engine's then differed; the manual's running heads, written inside their chapter `<section>`s, could not be patched. The lift bought nothing for rendering: `isFixedBox` takes a fixed box or a running element out of the word space, the feed and the presentation at any depth, a block that holds one is presented through a stripped copy, and every page's copy is made from the original where it stands (*a fixed box at any depth*). So `takeIntake` adopts only the top-level boxes, `presented.lifted` and its refusal are gone, and a replacement that is or holds a fixed box or a running element is still refused. `test/browser/nested-chrome.browser.ts` holds a fixed box and two running heads inside chapter sections over three pages: each page's text, read slot by slot, hashes as it did on main at `155ba49`, and a patch inside the first chapter answers an address and the run resumes. Under Chromium's own print the essay's eighteen chapters and its `fixedpos` reftests read the same on both sides; under Caster 0.1.7 they do not, and this waits on Caster: its Cicero adapter counts a divided block's words from the original, nested fixed box included, and refuses chapter 13 (*the block beginning on page 4 is not partitioned by its 2 fragments*), which printed on main. Egildo's ruling of 2026-11-08.
- **A running head leaves out a `::before` a printer made real.** Caster's preparation turns a heading's `::before` into a real `<span>` before the cut, and `content()` read it as the heading's own text, so `string-set: chapter content()` set "3. Results" where css-gcpm-3 reads "Results". Caster now marks every element it makes from generated content with `data-beltype-generated`, valued by its pseudo (`before`, `after`, `marker`), and `content()` in `string-set`, and the `content` keyword of `target-text()`, leave out what carries it (`contentTextOf` in `src/document-state.ts`). `content(before)` and `content(after)` read exactly the span of that pseudo where one was made, and fall back to the element's text, the stated limit, where the pseudo is still native. The name and its values are `GENERATED_ATTRIBUTE` and `GeneratedPseudo` in `@beltype/common/data-beltype`, not yet released; `src/` imports nothing, so the literal is spelled once, as `GENERATED_ATTRIBUTE` in `src/data-beltype.ts`, citing common's export. `test/browser/pseudo-counters.browser.ts` holds the head and `content(before)` over three prepared headings, red before.
- **The rim is a face: `@beltype/cicero/rim`.** `watchLateTruth`, `bringsNewFace` and `knowLoadedFaces` lived in `dist/seam/rim.js`, which the engine's own client imports, but no export reached them, since `./internal/*` maps `dist/src` only; a view that holds its own pages (prosemirror-beltype's) had to hand-roll its listeners for images, undefined elements, fonts and sizes. The new export is that same file, so a host's `knowLoadedFaces` and the client's share one record of the faces already announced. `test/faces.test.ts` holds that the face is the client's module and that a face told to it is one the engine knows (SPEC XIII.4; XIII.5 now says `./internal/*` is `src/` only, as it always was).
- **A `counter-reset: list-item` on an item of a divided list numbers as Chromium prints it, and four cases say so.** 0.1.9 named it unmodelled. Measured on Chromium's print, the reset changes no marker: the item that carries it and every item after print the list's own ordinal, under `reversed` too, and only a `counter(list-item)` the item's own content reads sees the reset. So `listOrdinals` was already right to leave it out, and its remark now says why. `test/browser/list-continuation.browser.ts` holds a reset before the cut, past the cut, in a `reversed` list, and beside a `counter-set`, each against Chromium's print; no code changed.
- **`counter(list-item)` read on a page a list continued onto, or past it, counts the items before it.** The counter walk in `src/document-state.ts` read only declared counter operations, and a list's reset of `list-item` and each item's increment are implicit, so a margin box's `counter(list-item)` read 0 on every page and `.x::after { content: counter(list-item) }` after a list read 0 on the next page where Chromium prints 6. The walk now logs them (`implicitListOps`): an `<ol>` resets `list-item` one step before its `start`, which under `reversed` defaults to the number of items, a `<ul>` or `<menu>` to 0; each element displayed as `list-item` adds 1, or −1 in a `reversed` list; an `<li>` of an `<ol>` is set to its `value`; and an author's own `counter-reset`, `counter-increment` or `counter-set` naming `list-item` replaces the implicit one. Chromium's own `counter(list-item)` counts a `reversed` list without `start` down from 0 and ignores `value`; the walk keeps HTML's numbering there, the one the markers print. `test/browser/list-continuation.browser.ts` holds four in-flow cases against Chromium's print and two margin-box cases against a counter the author increments by hand, since Chromium's print shows no document counter in a margin box; `test/document-state.test.ts` holds the arithmetic. Still read wrong, and named in the module's header: a scope that ended before a page with nothing logged in between, so a list whose last item holds a list reads the inner list's count on the page after it.
- **List continuation is held under the Compositor too.** Every case of `test/browser/list-continuation.browser.ts` that numbers a divided list's markers now runs a second time under `run({ composed: true })`, and all fifteen print as Chromium prints, since the copy's `start` is written by the fragment builders both modes share; the test also checks the run reports the mode it was asked for. No code changed.
- **The composed mode ends no more than three lines in a row on a hyphen.** In the first paragraph of the delibera specimen the Compositor ended seven lines in a row on a hyphen (*se-, rego-, im-, al-, Li-, produ-, so-*), where the browser's own lines stack at most four: total fit trades a hyphen for tighter spacing line by line, and the consecutive penalty only priced each pair. Varied on that paragraph, the penalty did not hold the run (seven at 3000, six at 10000, TeX's `\doublehyphendemerits`, three at 30000), so the Compositor's state is now the node and the run of hyphenated line ends behind it, and a run longer than its limit is not a candidate (`compose`'s `limitLines`, `HYPHENATE_LIMIT_LINES` in `src/compositor.ts`). The limit is three, Bringhurst's rule and the value css-text-4's `hyphenate-limit-lines` would carry. On delibera the longest run is three, the hyphens 10 for 13, and the interword space averages 1.356 of the natural space for 1.333, its spread 0.247 for 0.250 and its widest unchanged. With no limit the composition is the one it always was, and a paragraph the limit leaves no way through but an overfull line is set without it. An author's `hyphenate-limit-lines` is not read: Chromium does not support the property, so it never reaches computed style, and reading it needs a sheet rewrite like `string-set`'s. `test/browser/hyphen-limit-lines.browser.ts` holds the case over a sweep of measures (red at 150 mm with a run of five), and `test/compositor.test.ts` the limit's arithmetic. Codeberg issue 5; the `trattato` figures in the issue were not re-measured.
- **A page cut can fall at a line the browser hyphenated under `hyphens: auto`, with the hyphen on the page before, as Chromium prints it.** The Gauge refused every break between two letters under `auto`, because nothing in the DOM says whether the browser drew a hyphen there, so such a word was never divided: the page ended a line short and the whole word opened the next page, where Chromium prints `incomprehensi‐` at the foot of page one and `bility` at the head of page two. The browser does leave its hyphen in the range rects, an inked rect for the first character of the next line on the line the break ends, so the Gauge now opens a piece at such a break where it measures one (`drewHyphen`, `src/gauge.ts`), and the first fragment adds the hyphenation character, the author's `hyphenate-character` or U+2010, after the last kept letter (`consumeTrailingWords`, `src/fragments.ts`). The address carries no mark: the measurement decides which breaks are cuts, and the same predicate on the source decides what the cut writes. A break under `auto` that drew no hyphen is still not divided, and the composed mode's own break, whose hyphen is already written, gets no second one. `test/browser/hyphen-at-the-cut.browser.ts` holds the cases against Chromium's print, with an author `hyphenate-character` and an `overflow-wrap` break as guards; `test/fragments.test.ts` holds the writer's (assessment 2026-11-07, `auto-hyphen-cut-refused`).
- **The word space follows a table's display order.** Cicero numbers words in source order, and CSS 2.1 §17.2 shows a table's header group before its rows and its footer group after them wherever each is written, so a `<thead>` written after the rows had its words counted last while Chromium paints it first, and a `<tfoot>` written first had them counted first. 0.1.7 taught the cutter to walk such a header first, but the addresses still followed the source, so a header too tall to repeat was refused, and a footer written first that did not repeat printed on the table's first page where Chromium prints it on the last. Inside a table the word space is now counted in display order, header group, then rows and row groups as written, then footer group, by one function, `inDisplayOrder` in `src/word-space.ts`, which the position index, the paths, the Gauge, the fragments' cuts and the character walk behind `pageOf` all read. A late header too tall to repeat now prints first and once, and a footer too tall to repeat prints once at the table's end, as Chromium prints them; a footer written before its rows and taller than the page area is still refused by name. The 0.1.7 special cases are gone: the Gauge's `laidOutFirst` and `laidOutLast`, the Stonehand's refusals of a place beside such a group, `headerAfterRows` and the late-header refusal. `test/browser/table-groups.browser.ts` holds the three placements against Chromium's own print, and `test/word-space.test.ts` the order (SPEC I.1.8, I.2.1, VI.1.9; *the-word-space-follows-the-table-display-order*; assessment 2026-11-07, `thead-after-rows-and-tall-footer-lose-rows`).

## 0.1.9 — 2026-11-07
