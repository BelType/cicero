# Changelog

## Unreleased

- **A kept frame wears the words sheet and the values sheet again on its second print.** `ensureDressing` answered the record it kept per document, and `deliverValues` adopted the values sheet only the first time it made one, so a host that empties a kept document's `adoptedStyleSheets` before printing again (the CLI's kept page does) printed the second time without the engine's trimming rules, where the provision does not carry them, and without any `--beltype-slice` value, since no word was new. Both now ask the document whether it wears the sheet and adopt it again where it does not, and the layer is named again in the head, as the continuation dressing already did (*the engine asks the document for its sheets*). The red case is in `test/dressing.test.ts`.
- **A `target-text()` reference prints only the document's own text.** Its target was `getElementById`'s answer over the whole page, with no check that it stood among the blocks, so a host application's element carrying the same id as an author's (a toolbar label, a panel heading) had its text printed on the page and into the PDF. A target is now looked for among the originals the host hands, and a text target outside `blocksOf()`'s blocks shows nothing, as a counter or page target there already did. The red case is in `test/reads-hosts.test.ts`.
- **A run that answers `complete: false` is not taken for the whole document.** The reads loop showed the reservations and compared page values after every run, so a view whose chain stopped short (a page that failed) had its page numbers shown as `0` and its warm values replaced by the partial chain's. The loop now ends on such a run: the reservations stay hidden and the table it returns is the one the layout was cut under. The engine's own run is always complete and does not change. The red case is in `test/reads-hosts.test.ts`.
- **The page context's `counter-reset`, `counter-increment` and `counter-set` of the page counter number the pages as Chromium prints them.** `@page { counter-increment: page 2 } @page :first { counter-reset: page 5 }` printed 3, 4, 5, where Chromium prints 7, 2, 4, with no message: the declarations reached the page host as author style, where the increment was added to the host's own `page N` and the host's inline reset hid every `@page` reset. They are now withheld from the host and read into `pageNumberAt` (`document-state.ts`), with `pageFor` giving each kind of page its winning three (`pageCounter`, `capture.ts`). Measured on Chromium's print, each page box is its own scope: an increment and a set carry to the pages after (`@page :first { counter-set: page 7 }` prints 7, 8, 9), a reset shows on its page and does not carry (`@page :first { counter-reset: page 10 }` prints 10, 1, 2), and a page with a reset takes no implicit increment. An element's reset of the page counter, Cicero's own reading since 0.1.7, is applied before the page's own rules. `test/browser/page-context-counters.browser.ts` holds eight cases, the essay's counter probes and its want `the-restarted-count` among them, each printed by Chromium and by Cicero and read with pdf.js (assessment 2026-11-07).
- **A counter a `::before` or an `::after` sets is counted.** The counter walk read each element's own style and never its pseudo-elements', so a `target-counter()` to a figure numbered by `.fig::before { counter-increment: fig }` read 0, a `counter()` in a heading's `string-set` read the count before the heading's `::before`, and on screen each page started such a counter again: three figures, one a page, printed 1, 1, 1 where Chromium prints 1, 2, 3. `documentOpsOf` now logs a `::before`'s operations as the element's first child's and an `::after`'s as its last child's, at the element's end, where a sheet sets a counter on one (`sheetsCountInPseudos`); a pseudo-element whose `content` is `none` or `normal` is no box and counts nothing, as in Chromium. A reference and a named string read the element after its `::before` and before its `::after`, as WeasyPrint stores a target. `test/browser/pseudo-counters.browser.ts` holds the red cases (assessment 2026-11-07). Still not read, measured the same day: an `<ol>` that runs onto a second page numbers its items from 1 there under Cicero alone, `<ol reversed>` and an author's `counter-set: list-item 100` likewise; Chromium prints 12, 13 and so on.
- **A running head from a heading numbered by its `::before` reads the heading's text alone, and a case says so.** The assessment of 2026-11-07 reported `3. Results` where css-gcpm-3's `content()` gives `Results`. Cicero's `content()` reads the element's text, which holds no generated content, and prints `Results`, in 0.1.6 as in this release. The number comes from Caster: printed through the BelType CLI, Caster's preparation runs before the cut and turns `h2::before` into a real `<span class="caster-generated">` inside the heading, and `content()` reads that span's text. No change here; telling a reified span from the author's text needs a word the two packages share. The case is the third in `test/browser/pseudo-counters.browser.ts`.

## 0.1.7 — 2026-11-07

- **A header written after a table's rows is printed above them, and a footer written before its rows and taller than the page area is refused by name.** `<table><tbody>…25 rows…</tbody><thead>…</thead></table>` printed r0 to r10 and two blank pages, with no message: CSS 2.1 §17.2 lays the header out above the rows while its words stand after them, so the walk read the table as one box and sliced it. The Gauge now walks such a header first, as it walks a footer written first last (`headerAfterRows`, `laidOutFirst`), the Stonehand offers no place inside it or right after it, and a page before its words shows it by its repeated copy: page for page what the same table in HTML's order prints. One too tall to repeat, in a table a page divides, is refused naming the table, since which page shows it waits on the ruling on §17.2's display order in the word space. A `<tfoot>` written first and taller than the page area printed one page and lost every row after it; it is refused naming the table, because its words stand before the rows and its box after them, and only that ruling can place it. `test/browser/table-groups.browser.ts` holds the red cases (assessment 2026-11-07).
- **A forced break before a run of text falls before the run.** `<div><p style="break-after:page">a</p>run of text<p>b</p></div>` printed *a run of text* on page 1 and *b* on page 2, where Chromium prints *a* alone and *run of text b* after it. The run is an anonymous block box, and the forcing index walked elements only, so a `break-after` closing in front of it was carried past it to the next element. The index now holds an event at the first word of each run that follows a block child, in the word space of the box that holds it, as the Class A cut before a run is already spelled (*the anonymous box is in the procession*); the feed is cut at the first node after the child, and the Cast-off never names a run. The reach is every run after a block child carrying a pending `break-after`: a run between two blocks, a trailing run, one opening with an inline element, one after a nested last child or inside an inline wrapper, and one that ends the document, which used to stay on the page before. A run of whitespace alone is no box and changes nothing, and a `break-before` after a run was already right. `test/browser/forced-break-run.browser.ts` is the red case, each shape checked against Chromium's print.

- **A blank page made before a resetting element is not counted by its reset.** The blank the engine makes to bring a `break-before: recto` element to its side begins where the element does, so `pageNumberAt` counted it as the first page of the reset's scope: the element's page read 2 and `target-counter()` to the scope's end one too many (the `provvedimento-imu` batch, 2/4 to 4/4 for 1/3 to 3/3). The reset is now not in force on that blank, which continues the count it stands in, and the element's page bears the value; a blank inside the scope counts as every page does. The browser case is in `test/browser/page-counter.browser.ts`. Codeberg issue 13.
- **A vertical or sideways root is refused by name at intake.** Every read in this engine is horizontal, and under `:root { writing-mode: sideways-lr }` a positioned paragraph's text fell below the clip and was never resumed, which Caster's tiling invariant refused three tools later. `assertRenderConditions` now refuses a root whose `writing-mode` is not `horizontal-tb`, saying so. The two horizontal references of the same finding, `dimensions-013` and `014`, lose their characters to a `100vh` grid, the viewport-unit finding. Codeberg issue 12.
- **Three page lengths Chromium resolves are no longer refused.** A `size` in `em` (`size: 20em 7em`) is measured like any other length, against the root's font the probe wears; only a percentage refuses there, as css-page-3 §7.1 gives `size` none. An orientation keyword alone (`@page :first { size: portrait }`) turns the sheet the cascade's less specific rule gave, the longer side down or across, for a pair of lengths as for a named size, and refuses by name where no rule gave one, since this engine has no default sheet. A `var()` in a page-context shorthand (`margin: var(--margin)` with `:root { --margin: 20px 40px }`) is substituted from the root, which the page context inherits from (§4.1), before the shorthand is split; the two-value case refused as unresolvable because each side was seated with both values. `test/browser/page-lengths.browser.ts` holds the four cases. Codeberg issue 10.
- **A margin box's padding, border and margin reach its cell.** A box's own declarations went through the page host's filter, which withholds `margin-*`, `border-*` and `padding-*` because the Chase writes the page box's; `@top-left { vertical-align: bottom; padding-bottom: 5mm }` reached no cell and the running head sat on the content area (trattato, 13.6 pt off WeasyPrint). A cell's three are the box's own (`ownedOnCell`, `capture.ts`): only the `width` family and the grid seat stay the Chase's. `test/browser/margin-box-padding.browser.ts` is the red case. Codeberg issue 3.
- **An element's reset of the page counter counts on.** `counter-reset: page 1` on a chapter, or on each letter of a print run, left every page after it reading 1: the reset was delivered as an author counter to the flow and the margin cells, under the host's own `page N`, on every later page in its scope. The page counter is the host's, so the reset is folded into N (`pageNumberAt`, `document-state.ts`): the page the element begins on bears the value and the pages after count on from it, until the next reset. A `target-counter()` to a page reads the same N, so "Pagina 1/2" is 1/2 in the second letter too, where it read 1/4. Codeberg issues 1 and 2.
- **The root line-height provision is a floor again.** `:root { line-height: 1.65 }` in the head fragment has a specificity of (0,1,0) and beat an author's plain `html { font: 10pt/13.4pt … }` (0,0,1) silently: five of the six specimens printed at 1.65 instead of their declared leading (trattato 220 pages for 189). It is now `:where(:root)`, zero specificity: it still beats the browser's `normal` and loses to any author rule on the root. Codeberg issue 4.
- **An English word with punctuation attached has its hyphenation candidates.** The composed mode hands each word as it stands in the text, and English read only `/^[a-zA-Z]+$/`: `computer,` had no candidates, and no word at the end of a clause, before a full stop, inside quotation marks or brackets, or with a possessive `'s` ever broke. English now reads a word's core the way Italian does, with what stands around it moving no offset; an apostrophe inside a word stays no letter, as hyphen.tex was built for TeX. Codeberg issue 6.
- **The composed mode hyphenates Italian.** `lang="it"` now has Claudio Beccari's patterns, hyph-it.tex 4.9 (MIT), with two letters allowed on each side of a break, so *artico-lo* is a candidate. A language may say what counts as a word: Italian reads accented letters and elisions and leaves a word's punctuation around it, and English stays as it was. Until now an Italian paragraph that Cicero composed had no hyphens at all. Browser lines, the default mode, do not change.
- **A continuation of preserved text opens on the next line.** Consuming left the whitespace of every word cut away, which collapses under `white-space: normal` and under `pre`, `pre-wrap`, `pre-line` and `break-spaces` drew one empty line for each newline: a listing's second page opened on the first page's blank lines, and when they filled it the run refused with *entry position runs backward (I1)*. That whitespace now leaves the data where it is preserved, all but the indentation of the line the page opens on, and so does the whitespace after a fragment's last word. A blank line falling exactly at the head of a page goes with the cut, where Chromium keeps it (the essay's case of the blank line at the page head).
- **No break point stands in a repeated copy or beside it.** A table with a header whose first row under the copy did not fit took a place before where the page resumed, and the run refused the document with *entry position runs backward (I1)*. The row now divides under the copy, page for page with Chromium.
- **`@page` rules inside `@layer`, `@supports`, `@media` and imported sheets count** (`pageRulesOf`), and an unlayered rule beats a layered one whatever their order.
- **`cssString` escapes every control character**, so a carriage return or a form feed in a value cannot end the string.
- **Each measure context has its own container**, so two fills in flight do not measure in each other's.
- **The bands and the margin cells are `aria-hidden`.**
- `firstBelowTheEdge` is on the `fragmentation` face.

## 0.1.5 — 2026-11-03

- **Common 0.1.2**, the version that carries `@beltype/common/flags`.
- **The page's content area is as wide as the container it was measured in.** The page grid gave the band between the margins as three thirds, and Chromium lays out in 1/64 px and drops the remainder of each track: 112 mm (423.307 px) became 423.28125 px on the page and 423.296875 px in the measure container. A justified line that fits the second by a hair wrapped on the first, so the cut counted one line where the page showed two, and a paragraph the page could not hold was placed whole, its last line below the page area (trattato page 111, 9.7 pt, the only page of 220; on screen the flow's clip hid it, in print Caster put it beside the folio). `bandTracks` (`margin-boxes.ts`) gives three whole 1/64 px tracks that sum to the floor of the band, and `Chase.applyConditions` writes them. `test/band-tracks.test.ts` is the red case. Articles 139 to 141 of the specimen alone reproduce it (Caster's tiling invariant refused the print: 46 characters left below the clip); a hanging `float: left` number on the list items is what made the line a hair too long, and turning the float off made the specimen's two lines fit.
- **A linked sheet the rewrite replaces keeps its addresses.** A `<link>` whose sheet the rewrite changes becomes a `<style>` of the new text, and a `<style>` resolves `url()` against the document: a font declared inside `@media print` in `css/` was asked for at the document's root, because opening the print block is a change (the tester's case, 2026-11-03), and under a named layer every linked sheet was exposed. `rebaseUrls` (`seam/rewrite.ts`) now writes each relative `url()` and `@import` string against the link's href, in place; `data:`, absolute and `#fragment` addresses stay as written. `test/rewrite.test.ts` holds the red case.

- **`ciceroFlags`**, the run-wide flags in `@beltype/common`'s shape, exported from the host face (`@beltype/cicero`). One flag: `composed`, default `false`. `run()` behaves as before; the client runs in a tab that cannot resolve `@beltype/common`, so it keeps the literal default and a test pins it to the table. The call-level options `until`, `resumeAt` and `layer` are not flags.
- **Two light subpaths**, `@beltype/cicero/engine` (`ciceroEngine`) and `@beltype/cicero/flags` (`ciceroFlags`), so a host that never rewrites sheets does not load css-tree through the host face (about 24 ms in node).

## 0.1.0 — 2026-10-29

- **Cicero leaves the BelType monorepo.** `src/` and `seam/` move from `packages/engine-cicero` of `github.com/egildo/beltype`, at `main` f48afcef with the seventeen files that lacked types typed in place first (branch `round/the-org-drill`), into this repository, as TypeScript. The port is mechanical: a codemod turned the JSDoc types into annotations, and each of the 36 emitted `.js` files reads the same as the `.js` it came from once both are minified with comments dropped. The code is unchanged.
- **Five faces** replace deep paths: `.` (the host), `./client`, `./facsimile`, `./fragmentation` (the 67 values and one type a view imported by path), and `./internal/*`, unstable. Nothing is un-exported.
- **The engine seam's contract** travels as `seam/engine.ts`, from BelType's `packages/common/src/engine.js`, which `@beltype/common` does not carry.
- **Tests**: the 29 engine suites run on `node:test` from `.ts` (382 tests), with two new ones: the pin between `@beltype/common`'s grammar and the engine's registry, and the layering test. BelType's decisions test stays there with the decision records.
